# 目标循环

## `/goal`

发送 `/goal <条件>` 为当前 Agent 设置目标。Claude 使用原生目标机制，Codex
使用 OSS 已有的 Bridge 目标循环。飞书响应卡片会持续显示目标徽标。

- `/goal status` 查看目标；`/goal clear` 清除目标，不重置对话。
- `/stop` 中止当前任务并清空排队消息。
- `/reset` 及别名 `/new` 清除执行会话、排队消息、目标和目标徽标，保留工作目录。
- OSS 内部故障恢复调用的会话重置也会清除已保存的目标。

## `/auto [目标]`

Shadow Mode 根据已完成的问答生成下一条用户消息，并以主机已授权的飞书/Lark
用户身份发送、提及当前 Agent。它不使用工具轨迹，与 `/goal` 的驱动方式不同。

| 命令 | 效果 |
| --- | --- |
| `/auto` | 立即启动，没有历史问答也会生成第一条消息 |
| `/auto <目标>` | 带目标启动，或替换自己正在运行的目标 |
| `/auto status` | 只查看状态，不会启动循环 |
| `/auto stop` | 停止自动发送后续消息 |

运行期间，普通消息作为补充输入，不会接管或停止循环。消息对应的完整问答加入
上下文后继续自动推进。只有本轮发起者可以通过 `/auto` 修改目标或停止。
设置目标时，Shadow 模型可在判断目标完成且已验证后发出结束信号，MetaBot
随即停止，不再发送下一条用户消息。这是模型判断，不是独立验证。
未设置目标时，没有自动完成条件或固定轮次上限，请监控用量并主动停止。
执行 Agent 原有的权限、审批和预算限制不变。

### 配置与隐私

`/auto` 默认关闭。管理员须通过 `METABOT_AUTO_ALLOWED_USER_IDS` 明确允许
发起者（以逗号分隔的用户 ID）。仅在可信聊天中启用：被允许的用户可以驱动
主机已授权的用户身份。

渠道需要支持以用户身份发消息，并知道当前 Bot 的 open ID 以便提及。默认使用
主机单独授权的 `lark-cli` 用户会话，支持通过 `LARK_CLI_PATH` 指定程序。
也可选用仅在运行时提供的 `METABOT_SHADOW_USER_ACCESS_TOKEN`；不要将令牌
写入仓库、Bot 配置、日志或消息。令牌应属于预期的飞书/Lark 身份，并拥有向
目标聊天发送消息的权限。MetaBot 不安装、更新或重新授权 `lark-cli`。

生成使用无工具的隔离会话。可在 Bot 工作目录放置可选的
`.metabot/shadow-profile.md`，但不要在其中放凭据。Shadow 自身的问答缓存默认
只保留在内存；底层 Engine 仍可能按其正常会话策略持久化生成提示。
活跃循环不会在重启后恢复。飞书/Lark 话题回复仍发送到原话题。

## `/resume`

选择器按“相对时间 · 会话标题”展示。无标题时依次回退到首条提示预览、会话 ID
前缀。说明栏保留 ID 前缀、当前会话标记，以及与标题不同的提示预览。
`/resume <ID 前缀>` 仍可直接按 ID 恢复。
